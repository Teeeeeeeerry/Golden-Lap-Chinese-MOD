# 译文数据格式

译文按字符串表分三份 JSON 存于 `translations/zh-Hans/`：`Content.json`、`Menus.json`、`Events.json`。

每份是一个对象，键为翻译条目的 `m_Id`（数字，写成字符串），值为：

| 字段 | 含义 |
| --- | --- |
| `en_hash` | 英文原文的哈希：UTF-8 的 sha256 取前 16 位十六进制。仓库不存英文原文本身，原文在构建时从玩家本地游戏文件提取。 |
| `zh` | 简体中文译文。占位符（如 `{otherDriver}`）、富文本标签（如 `<b>`）与换行须原样保留。 |
| `status` | 校对状态：`mt` 机翻、`ok` 已校对、`stale` 英文原文已变、待复核。 |

示例：

```json
{
  "248174071668736": {
    "en_hash": "…",
    "zh": "生涯",
    "status": "ok"
  }
}
```

文件按 `m_Id` 数值升序写出，便于审阅差异。校验：`python -m glzh validate`；本机装有游戏时还会核对每条译文的占位符、富文本标签、字面转义（如 `\n`、`\u2022`）和换行数是否与英文原文一致（英文序数词后缀 `{ordinalSuffix}` 中文可省略）。

首版译文为 LLM 机翻初稿，全部为 `mt`，待逐条校对后改为 `ok`。英文原文为空的条目无需翻译；土耳其语包有 20 行英文包没有的空行，构建时写为空串，也不需要翻译。因此三张表共 654 条需要翻译（Content 228、Menus 336、Events 90）。英文包另有的 Race UI 表不在土耳其语包中，不翻译（见 ADR 0001）。

## 游戏更新后

运行 `python -m glzh diff`，按 `m_Id` 比对玩家本地英文原文的哈希与仓库 `en_hash`：

- **待译**：游戏里新出现的 `m_Id`，需要补译文。
- **原文改动**：英文原文变了（含变为空串）。加 `--write` 会把这些条目的 `en_hash` 更新为新哈希、`status` 置为 `stale`，译文保留待人工复核；复核后改回 `ok`。
- **废弃**：仓库里有、游戏里已没有的 `m_Id`，保留不删，由维护者决定是否清理。

报告同时给出仍处于 `stale` 的条目总数。`python -m glzh build` 构建前也会打印这份报告，但不写回：构建在玩家本地运行，不改仓库译文。英文原文为空且尚无译文的条目无需翻译，不计入待译。

车队名、赛道名、人名等专有名词保留英文原文，不做翻译，与游戏数据文本中的写法保持一致。
