# 在 catalog 中追加登记土耳其语的 Race UI 表

**Status:** accepted（部分取代 ADR 0001 中「比赛界面的 Race UI 表保持英文」的结论）

英文包除 Content、Menus、Events 外还有一张 Race UI 表（约 126 条，比赛界面文本），土耳其语包没有这张表，顶替土耳其语的简体中文因此回退英文。ui 包有 106 个组件、`level2` 场景有 31 个组件引用这张表，程序集里也有一处按表名直接取字。比赛是游戏的主体，这部分英文影响最大。

决定：构建时以英文包的 `Race UI_en` 为模板，在土耳其语字符串表包中新建 `Race UI_tr` 表，并在 catalog 中为它追加登记：
- 新增一个位置条目：内部 ID 为新表的资源路径；提供者和资源类型照抄 `Race UI_en`；依赖照抄 `Menus_tr`，即土耳其语包。
- 新增两个键：地址 `Race UI_tr`，以及由地址哈希得到的资源 GUID。
- 把条目追加进已有的 `Locale-tr` 标签。`Race UI_en` 没有 Preload 标签，这里也不加。

键、桶、条目三个数据段都只在末尾追加，已有内容及其下标不变，与 CRC 置 0 的原位改动互不干扰。

与 ADR 0001 否决做法的区别：当时否决的是新增第 9 种语言，需要注册新的资源包、改写多处依赖；这次不新增包，只给已有的包追加一个资源，而且每个字段都照抄同类条目。土耳其语包与英文包结构相同（同一个 StringTable 脚本，同样以共享键表包为外部引用），模板表里的引用直接有效，不需要新增依赖。

**Considered Options:**
- **改引用（ADR 0004 式）**（否决）：把 ui 包与 `level2` 场景中对 Race UI 的引用改指 Menus 表的新增条目。程序集里按表名取字的那一处改不到，还要多改一个场景文件。
- **维持英文**（否决）：比赛界面是玩家停留最久的地方。

**Consequences:**
- 构建时，catalog 中找不到 `Race UI_en`、`Menus_tr`、`Locale-tr`，或者已有 `Race UI_tr`（例如将来官方自带土耳其语 Race UI），都会中止并报错，不写出可能导致游戏打不开的文件。英文包没有 Race UI 表时同样中止。
- 译文从三张表变为四张。
