# 写死的界面文本改为引用新增的字符串表条目

**Status:** accepted

ui 包中有些界面文本直接写在文本组件（游戏自定义的 `FunTextTMP`）上，组件的本地化引用为空，不来自字符串表，例如主菜单右下角的「our new game」。这类文本不会随语言切换，顶替土耳其语后仍显示英文。

决定：不直接改组件上的文字。在 Menus 表新增一个翻译条目，英文行写组件原文，土耳其语（简体中文）行写译文；共享键表登记这个条目；再把组件的本地化引用指向它。新增条目的 `m_Id` 由语义键哈希得到，落在保留区间 `[2^62, 2^63)`，与游戏自身的条目不会冲突，更新比对时可直接识别并忽略。组件按原文哈希定位，不依赖对象 path_id，仓库也不存英文原文。

理由：直接改组件文字，所有语言都会显示中文。改成引用条目后，其他语言缺这一行时会回退英文，显示与原版一致。

**Considered Options:**
- **直接改组件的 `m_text`**（否决）：改动最小，但英文、德文等语言也会显示中文。
- **引用已有的相近条目**（否决）：例如「Wishlist our new game!」。原文不同、更长，会改变其他语言的显示，还可能溢出按钮。

**Consequences:**
- 除土耳其语包外，还要改写共享键表包与英文字符串表包，二者都经 catalog 加载，CRC 置 0（与 ADR 0001 的做法一致；只在现有表内加条目，不在 catalog 中注册新包）。
- 只处理确认为静态可见的写死文本。大量引用为空的组件是运行时由代码覆盖的占位文本（数字、人名、"Card title" 等），无需处理。
- 游戏更新后若原文变了，组件找不到会被跳过，该处回到英文。
