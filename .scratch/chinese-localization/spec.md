# Spec：Golden Lap 简体中文汉化

## Problem Statement

Golden Lap（Steam appid 2052040，Unity 2022.3.62f2，macOS 为 arm64/x86_64 通用二进制）内置 8 种界面语言，不含中文。游戏自带的官方 MOD 系统只加载数据文本与图片，无法替换界面文本或字体，因此无法通过创意工坊订阅获得中文界面。中文玩家缺少可用的简体中文界面。

## Solution

提供一个在玩家本地运行的安装器，把一张简体中文字符串表注入游戏，顶替土耳其语这一语言选项，并向 TMP 主字体注入思源黑体后备，使简体中文在游戏内正常渲染。安装器可重复运行、可还原；译文与字体子集由项目维护，发布包只含自有资源。玩家在游戏语言菜单选择"简体中文"即获得中文界面。

## User Stories

1. 作为中文玩家，想在游戏语言菜单看到"简体中文"一项，以便切换到中文界面。
2. 作为中文玩家，想让所有菜单、按钮、提示显示为简体中文，以便无障碍操作游戏。
3. 作为中文玩家，想让赛事事件提示显示为简体中文，以便理解比赛中的情况。
4. 作为中文玩家，想让界面中文字形完整显示、不出现方框缺字，以便正常阅读。
5. 作为中文玩家，想双击一个安装器即完成全部汉化步骤，无需手动改配置或敲命令。
6. 作为中文玩家，想让安装器自动定位 Steam 游戏目录，以免手动查找路径。
7. 作为 macOS 玩家，想让安装器自动解除下载文件的隔离属性，以免被 Gatekeeper 阻拦。
8. 作为中文玩家，想在安装前自动备份被改动的原始资源包，以便随时还原。
9. 作为中文玩家，想用一个还原脚本把游戏恢复到未汉化状态，以便排查问题或彻底卸载。
10. 作为中文玩家，在游戏更新或"验证文件完整性"把汉化覆盖后，想重跑同一个安装器即可恢复中文。
11. 作为切换语言的玩家，想随时切回英文或其他原有语言（土耳其语除外），以便对照。
12. 作为译者，想按 Content、Menus、Events 三张字符串表分别维护译文，以便分类校对。
13. 作为译者，想让每条翻译条目带键、英文原文哈希、译文、校对状态，以便追踪质量与变更。
14. 作为译者，想用 LLM 机翻先生成初稿并标记为机翻状态，以便快速铺底再逐条校对。
15. 作为译者，想把校对过的条目标记为已校对，以便区分可信译文与待校对译文。
16. 作为维护者，想在游戏更新后得到一份差异报告，列出新增、原文改动、废弃的条目，以便增量维护。
17. 作为维护者，想让原文改动的条目自动标记为待复核，以便不遗漏需要重译的文本。
18. 作为维护者，想让英文原文不进入公开仓库、仅在本地从玩家游戏文件提取，以避免再分发游戏原文。
19. 作为维护者，想让发布包与创意工坊物品只含自有资源（思源黑体子集、译文），以规避版权风险。
20. 作为维护者，想按译文实际用到的字生成字体子集，以控制注入体积、避免打入全字库。
21. 作为维护者，想在补繁体时只需扩充字体子集并新增一份译文，而无需改动整体架构。
22. 作为维护者，想在 Steam 创意工坊放一个纯引流说明物品指向 GitHub，以便扩大曝光但不分发内容本体。
23. 作为维护者，想让安装器与译文数据按跨平台编写，以便后续仅补一个 Windows 安装器即可支持 Windows。
24. 作为开发者，想在不启动游戏的前提下用 UnityPy 读回注入结果做自动校验，以便快速验证补丁正确。
25. 作为开发者，想先做一个最小验证（注入字体 + 一句中文、进游戏确认渲染）再铺开全部译文，以便尽早暴露字体注入风险。

## Implementation Decisions

- **总体方式**：直接修改游戏文件，不使用 BepInEx 或任何运行时注入（见 ADR 0001）。
- **语言占位**：以简体中文顶替土耳其语——整体替换 `localization-string-tables-turkish_assets_all.bundle` 的内容，并在 locales 包中把该语言显示名改为"简体中文"。不新增第 9 种语言，`catalog.json` 结构不改动（见 ADR 0001）。
- **字符串表**：三张表 Content、Menus、Events，共约 678 条，以数字 `m_Id` 为跨语言共享键。汉化即按 `m_Id` 将英文映射为中文后写回土耳其语包。
- **字体**：仅用 SIL OFL 字体，界面统一思源黑体（Noto Sans CJK SC）。按译文实际用字做静态 SDF 子集，作为后备注入 TMP 主字体 `LiberationSans SDF`，使缺字回退到中文字形（见 ADR 0002）。
- **字体所在包**：字体资源位于带内容哈希命名、体积较大的 `ui_assets_all` 包中。注入须保持其文件名不变，以免 `catalog.json` 引用失效。此为最高工程风险点，先以最小验证确认可行。
- **构建位置**：安装器仅在玩家本地读取其游戏文件并注入；发布包只含自有资源，绝不含游戏原始资源（见 ADR 0002）。
- **译文数据**：仓库按表存 `Content.json`、`Menus.json`、`Events.json`，以 `m_Id` 字符串为键，值含 `en_hash`（英文原文哈希，不存原文）、`zh`（译文）、`status`（`mt` 机翻 / `ok` 已校对 / `stale` 待复核）。英文原文构建时从玩家本地游戏文件实时提取。
- **更新比对**：构建时按 `m_Id` 比对玩家当前游戏英文原文的哈希与仓库 `en_hash`——新 `m_Id` 为待译，`en_hash` 变化则该条置 `stale`，`m_Id` 消失为废弃。输出一份差异报告。
- **安装器职责**：定位 Steam 游戏目录、备份原始 `turkish` 与 `ui_assets_all` 包、执行注入、解除隔离属性（`xattr`）；可重复运行，每次重新打补丁。
- **还原**：提供还原脚本，从备份恢复原始资源包。
- **工具链**：Python + UnityPy 读写 Unity 2022.3 资源包。
- **平台**：macOS 先行；译文数据与注入逻辑按跨平台编写，Windows 安装器留第二阶段。
- **许可**：安装器/脚本 MIT，译文 CC BY-NC-SA 4.0。

## Testing Decisions

- **什么是好测试**：只验证外部可观察行为，不绑定实现细节。注入类测试以"用 UnityPy 重新读回补丁产物、断言内容符合预期"为准，不依赖函数内部步骤；比对与数据校验类测试以纯函数的输入输出为准。
- **主 seam（最高、首选）**：一个在内存中进行的纯函数——输入原始本地化资源包字节与按 `m_Id` 的译文映射，输出注入后的包字节。测试用 UnityPy 读回产物，断言各 `m_Id` 的 `m_Localized` 等于译文映射，且未触及其他结构。全程不启动游戏。
- **字体注入 seam**：函数输入 `ui_assets_all` 字节与中文字体资源，输出注入后字节。自动测试只断言产物中存在中文字体资源且主字体后备链已指向它（确定性部分）；"中文在游戏内真实渲染"由最小验证票人工确认，不做自动化。
- **差异比对 seam**：纯函数，输入当前游戏按 `m_Id` 的英文哈希与仓库 `en_hash` 映射，输出新增/改动/废弃三类清单。
- **译文数据校验 seam**：纯函数，校验三份 JSON 的键完整性与 `status` 取值合法。
- **字体子集 seam**：纯函数，输入全部译文文本，输出所需字形集合。
- **先例**：项目尚无测试，这些是首批测试，按上述纯函数 + UnityPy 读回的范式建立。

## Out of Scope

- 数据文本（车队、车手、赞助商、事件等 `Data/**` 内容）的汉化。
- 繁体中文（架构预留，不在首期实现）。
- Windows 安装器（逻辑跨平台，安装器实现留第二阶段）。
- 把汉化本体上传创意工坊（工坊仅作引流说明，不分发内容）。
- 消除"游戏更新后需重跑安装器"这一限制（A1 方案固有代价，见 ADR 0001）。
- 任何运行时注入 / BepInEx 方案。

## Further Notes

- 可行性已验证：UnityPy 能读写这些资源包，字符串表重打往返测试通过；土耳其语包含 Content(252)/Menus(336)/Events(90) 共 678 条。
- 字体注入 `ui_assets_all` 为最高风险，故实现从"注入字体 + 一句中文 → 进游戏确认渲染"的最小验证票起步，通过后再铺开全部译文与安装器。
- 术语一律使用 GLOSSARY.md 词汇；决策遵循 docs/adr/0001、0002。
